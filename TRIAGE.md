# Triage: Severe Planning-Phase Slowdown in `PushDownFilter`

## 1. Issue Description

### Short summary
`PushDownFilter` is a disproportionate planner hotspot in the `sql_planner_extended` benchmark, with heavy time spent in expression type/nullability inference (`ExprSchemable::get_type`, `nullable`, `to_field`) during recursive rewrites and join predicate inference.

### Observed behavior
- `push_down_filter` dominates planner runtime (reported ~174s in profiling), far above peer rules.
- Flamegraph stacks are dominated by expression schema/type/nullability paths:
  - `Expr::get_type`
  - `ExprSchemable::get_type`
  - `nullable`
  - `to_field`
  - `PredicateBoundsEvaluator::evaluate_bounds`
- Runtime amplification appears with deep plans generated by repeated `with_column`, `filter`, and `union_by_name` in [`datafusion/core/benches/sql_planner_extended.rs`](/Users/kosiew/GitHub/datafusion/datafusion/core/benches/sql_planner_extended.rs).

### Expected behavior
- `PushDownFilter` should be in the same rough runtime class as other optimizer rules (ms to low s for this benchmark class).
- Type/nullability evaluation should not dominate planning.
- Rewrites should avoid repeated recomputation on equivalent expression subtrees.

## 2. Codebase Review

### Files/modules involved and key data shapes
- Core rule: [`datafusion/optimizer/src/push_down_filter.rs`](/Users/kosiew/GitHub/datafusion/datafusion/optimizer/src/push_down_filter.rs)
  - `OptimizerRule::rewrite` (`ApplyOrder::TopDown`) rewrites many node kinds (Filter, Join, Projection, Aggregate, Window, TableScan, Extension, Union).
  - Frequent conjunction split/rebuild (`split_conjunction_owned`, `conjunction`) and expression cloning.
  - Join path infers predicates and conditionally evaluates null-restrictiveness for non-inner joins.
- Null-restrictiveness helper: [`datafusion/optimizer/src/utils.rs`](/Users/kosiew/GitHub/datafusion/datafusion/optimizer/src/utils.rs)
  - `is_restrict_null_predicate` -> `evaluate_expr_with_null_column` -> `coerce` + `create_physical_expr` + `evaluate`.
  - This path can recursively trigger expression type/nullability derivation.
- Expression schema/type/nullability: [`datafusion/expr/src/expr_schema.rs`](/Users/kosiew/GitHub/datafusion/datafusion/expr/src/expr_schema.rs)
  - `ExprSchemable::{get_type, nullable, to_field}`.
  - `nullable` for `Expr::Case` uses predicate bounds evaluation for branch reachability.
- Predicate bounds evaluator: [`datafusion/expr/src/predicate_bounds.rs`](/Users/kosiew/GitHub/datafusion/datafusion/expr/src/predicate_bounds.rs)
  - Recursive `evaluate_bounds` with repeated `get_type` / `nullable` checks.
- Optimizer pass loop: [`datafusion/optimizer/src/optimizer.rs`](/Users/kosiew/GitHub/datafusion/datafusion/optimizer/src/optimizer.rs)
  - All rules execute per pass until fixed point (`max_passes`), so expensive rules are multiplied by pass count.

### Design patterns (name + evidence)
- Rule-based top-down rewrite:
  - `PushDownFilter::apply_order()` returns `TopDown`.
- Fixed-point multi-pass optimizer:
  - `Optimizer::optimize` loops rules across passes until plan signature repeats.
- Conjunction decomposition/recomposition:
  - widespread `split_conjunction_owned` / `conjunction` use for partial pushdown.
- Predicate inference by symbolic column substitution:
  - `infer_join_predicates_impl` builds replacement map from join keys.
- Expression-level semantic checks via null evaluation:
  - `is_restrict_null_predicate` evaluates predicates with null-substituted columns via physical expr path.

## 4. Resolution Plan

### Root cause (concise)
Likely a design-level cost explosion from repeated expression type/nullability derivation in `PushDownFilter` rewrite and non-inner join predicate inference, amplified by recursive rule traversal and optimizer multi-pass execution.

### Category
Design (with possible regression contributions from recent nullability/join-inference changes).

### Evidence & reproduction
- Existing reproduction command:
  - `RUST_LOG=info cargo samply --profile=release-nonlto --bench sql_planner_extended -- --nocapture --sample-size 10`
- Local code evidence:
  - `PushDownFilter` top-down rewrite across many node kinds.
  - Non-inner join inference calls `is_restrict_null_predicate`.
  - `is_restrict_null_predicate` may build/evaluate physical expressions with null-substituted inputs.
  - `ExprSchemable::nullable` and `predicate_bounds::evaluate_bounds` recurse into type/nullability checks.

### Short fix checklist
1. Add test/bench that reproduces planner-time blowup.
2. Implement fix and run targeted tests/bench.
3. Add debug timing counters for `PushDownFilter` subpaths (join inference + null-restrict evaluation) to validate improvements and catch regressions.
4. Prepare rollback path:
   - Keep a config/guard to disable aggressive inferred pushdown for non-inner joins if needed.
5. Open PR with RCA, before/after benchmark numbers, and added coverage.

3. Benchmark and verify no semantic change.

Sub-issue D: Reduce rewrite churn in `PushDownFilter`  
Mini-plan:
1. Replace avoidable clone-heavy conjunction operations with borrowed iteration paths.
2. Add micro-bench checks around union/projection-heavy plans.
3. Land behind small, reviewable PR(s).
